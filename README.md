# DecMarkt Protocol (Powered by Jev)

DecMarkt is a complete Solidity protocol built with Foundry that serves as the accountability and execution layer for the **Jev** decision-making engine.

While Jev operates off-chain to evaluate state and generate structured decisions (choices, scores, and probabilities), the DecMarkt smart contracts enforce the resulting bounded protocol state, ensuring deterministic, reproducible, and secure execution.

## 🏗 System Architecture

The protocol is composed of four core smart contracts:

1. **`DecisionRegistry.sol`**: The core state machine tracking the lifecycle of all decisions.
2. **`DecisionEngine.sol`**: Handles deterministic aggregation of agent submissions.
3. **`ExecutionVault.sol`**: A highly restricted execution environment for approved actions.
4. **`OutcomeRegistry.sol`**: Immutable ledger of expected vs. observed results.

---

## ✨ Core Features

### 1. Decision Lifecycle Management (`DecisionRegistry`)
Every decision goes through a strictly bounded lifecycle:
`CREATED` ➔ `OPEN` ➔ `AGGREGATED` ➔ `APPROVED` ➔ `EXECUTED` ➔ `RESOLVED` (or `CANCELLED`)

The registry immutably stores:
- `decisionId`
- `stateHash` (cryptographic link to off-chain state)
- `questionSetHash`
- `threshold` & `deadline`
- `status` & `createdAt` timestamp

### 2. Secure Agent Submissions
Agents submit structured decisions generated by Jev. The protocol rigorously validates all inputs.
- Submissions require: `agent` address, `decisionId`, `questionId`, `choice`, `score`, `probability`, and a financial `bond`.
- **Protections**: Strict prevention of duplicate submissions and rejection of expired decisions.

### 3. Bounded Choices
To maintain deterministic outcomes, DecMarkt strictly enforces bounded choices. Any unsupported choices are automatically rejected by the smart contracts. Supported choices include:
- `NO_ACTION`
- `ACTION_A`
- `ACTION_B`
- `ESCALATE`

### 4. Deterministic Decision Engine (`DecisionEngine`)
The engine uses a fully documented, independently reproducible formula to aggregate Jev's structured outputs (`Choice`, `Score`, `Probability`). It deterministically calculates the aggregate score, verifies if the `threshold` is met, and selects the approved action.

### 5. Sandboxed Execution (`ExecutionVault`)
Security is paramount in the execution layer. The Execution Vault only executes **predefined actions**.
- 🚫 **NO** arbitrary contract calls.
- 🚫 **NO** arbitrary calldata.
- 🚫 **NO** AI-generated transaction instructions.

### 6. Settlement & Outcome Tracking (`OutcomeRegistry`)
- **Outcome Registry**: Records the `decisionId`, `expected action`, `observed result`, `success` boolean, `outcome value`, and `timestamp`.
- **Settlement**: Deterministic distribution of bond returns, rewards for correct/consensus decisions, and penalties/slashing for malicious or incorrect inputs.

## 🔒 Security Guarantees

The protocol adheres to strict smart contract security standards:
- Comprehensive **Access Control** on all sensitive functions.
- Gas-efficient **Custom Errors** and comprehensive **Events** for off-chain indexing.
- Strict **Deadline Validation** and **Duplicate Prevention**.
- **Reentrancy Protection** on all state-mutating functions (especially during settlement/execution).
- Adherence to the **Checks-Effects-Interactions** pattern.
- Strict avoidance of `tx.origin`.
